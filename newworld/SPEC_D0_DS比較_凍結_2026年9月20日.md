# D0 と D_S-exact の比較仕様 — ★結果を見る前に凍結★ — 2026年9月20日

**この文書は D_S-exact を解く前に書いた。以後、結果を見てから測り方を足さない。**

## 1. D_S-exact の実装（両監査が承認）

報酬の形に落とさず、**V_t(s) = その状態から天寿に到達する確率**として直接解く。

```
t=999 : その1歩を実行し、
          飢え死 → 0 ／ 急所死 → 0 ／ 生き残った枝 → 1（天寿）
        decision なら Q_999(s,a) = Σ_{生存した枝} p、V_999(s) = max_a Q_999(s,a)
        ★V_1000 は不要★
t<999 : Q_t(s,a) = Σ_{非終端 s'} p(s'|s,a) · V_{t+1}(s')
        飢え死・急所死の枝は 0
        強制 MODE は max を取らず、その MODE の遷移をそのまま評価する
```

**★1000歩目でも急所死・飢え死が天寿より優先する★**（「1000歩目だから先に成功」ではない）。
kernel のその1歩を全部処理して、**生き残った枝だけ 1**。捕獲の摂取で飢え死を回避する同一歩の順序もそのまま。

**selected policy は D0 とまったく同じ凍結済みの tie 判定と固定順序を使う**（`selected_common` を共通関数として使い回す。P1c の事故を繰り返さない）。

## 2. 比較の測定項目（★これを固定する。結果を見てから足さない★）

### 2-1. 方策の一致（★selected だけでなく optimal_set も★）
分母は **structural-valid な decision 状態 × t=0..999**（E=0 などは混ぜない）。
- selected action の一致率
- **optimal_set の完全一致率**
- **D0 の selected ∈ D_S の optimal_set** の割合
- **D_S の selected ∈ D0 の optimal_set** の割合

### 2-2. 占有率で重み付けした不一致
- **D0 の占有率で重み付け**（D0 が実際に通る世界でどれだけ違うか）★本体★
- **D_S の占有率で重み付け**（D_S が実際に通る世界でどれだけ違うか）★本体★
- 両者の平均（補助。見やすい要約として置くだけ）

### 2-3. ★cross-objective regret（ChatGPT の追加。最重要）★
```
π_D0 を使ったときの  P(天寿)     と  E[T]（= 998.520049）
π_DS を使ったときの  P(天寿)（= D_S の最適値）と  E[T]
```
**「寿命最大化の方策を使うと、天寿確率をどれだけ失うか」**
**「天寿確率最大化の方策を使うと、期待寿命をどれだけ失うか」**

追加の Bellman は不要。**各方策の前向きを1回ずつ走らせれば、同じ前向きから期待寿命・天寿確率・死因の分布が全部出る。**

### 2-4. 帯構造（★D_S でも独立に RLE する★）
同じ断面（t=0, W=0, N_S=12, N_L=3, E=1..2000、列は 1..19,0）で、
**D_S 側も先入観なしに100行を run-length encode する。**
その結果を見てから「何種類出たか／D0 の6種類と何種類一致したか」を比較する。
**★「D0 の6種類が D_S にもあるか」を直接探さない★**

### 2-6. r=6/7 の Q 不連続
**D_S でも r=6/7 周辺の Q_grass / Q_small を測定する。**

## 3. 実行の順番（★両監査が一致★）

```
本仕様のコミット
  → ★D0 の前向き（約19分）★
       ・E[T] = 998.520049 を独立に再構成できるか
       ・質量の保存
       ・天寿／飢え死／急所死の最終質量
       ・★W=10 の占有率とあふれの質量★（異常②の材料。事前登録済みの K 感度に関わる）
  → D0 の前向きの結果を固定
  → D_S solver の回帰テスト（t=999 の扱い、t=998→999 の接続）
  → D_S の後ろ向き（約26分）
  → D_S の前向き（約19分）
  → 比較
  → 必要なら D0 の前向きをもう一度だけ走らせて、占有率で重み付けした不一致を流し計算
     （占有率を何GBも保存するより安全）
```

**D0 の前向きを先にやる理由**
1. **後ろ向きで得た V0 = 998.520049 を、独立した前向きで再構成できるかの検証**になる
2. 天寿・飢え死・急所死の最終質量が初めて出る
3. **★異常②（W=10 で大物）の材料★**：K=10 のあふれ近似が実際の D0 方策でどれだけ踏まれるかは、前向きを流さないと分からない
4. OOM や watchdog の介入があっても、D0 単体で完結したデータが残る

**この方針は correctness > reproducibility > simplicity > speed の凍結に沿う。**
