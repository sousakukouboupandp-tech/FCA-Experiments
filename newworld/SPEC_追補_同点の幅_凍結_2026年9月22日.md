## 1. 問題
D0 と D_S の方策は、最適行動の集合（optimal_set。numerical tie の許容つき）の中から
固定順序（草→小物→大物）で1つ選んでいる。
- D0 の天寿率 0.851102 は「D0 最適で、同点なら草」の方策の値にすぎない
- π_DS の期待寿命も「D_S 最適で、同点なら草」の方策の値になる（天寿が絶望的な状態では全行動が確率0で同点）
→ ★目的どうしの比較（14ポイント差、cross-objective regret）が、同点の決め方に左右されうる★

## 2. 追加する計算（行動を最適集合に制限した MDP を後ろ向きに解く）
保存済みの optimal_set.dat（D0・D_S とも1000時刻ぶん）を使う。強制 MODE は選択なし。

【D0 側の1パス】行動を OptSet_D0(s,t) に制限し、天寿到達確率を3通りで同時に解く
- P_max = D0 最適な方策の中での天寿率の最大（＝「D0 優先、次に D_S」の辞書式最適）
- P_min = 同じく最小
- P_eval = 固定順序で選んだ π_D0 の天寿率（★方策評価。前向きの 0.851102 と一致するはず★）

【D_S 側の1パス】行動を OptSet_DS(s,t) に制限し、期待寿命を3通りで同時に解く
- T_max ／ T_min ／ T_eval（固定順序の π_DS の期待寿命）

終端・horizon の扱いは凍結済みの D0 / D_S と同じ（t=999 の非終端は天寿、V_1000 不要、不利な死が優先）。
max / min は制限した集合の中で厳密に取る（ここでは tie の許容を使わない）。

## 3. 検証（★これが通らなければ解釈しない★）
- D0 側：P_eval と前向きの 0.851102 の差 ≤ 1e-9
- 不等式：P_min ≤ P_eval ≤ P_max ≤ 0.990589612
- 不等式：T_min ≤ T_eval ≤ T_max ≤ 998.520049
- T_eval は、D_S の前向き（凍結済みの手順）で出る期待寿命と差 ≤ 1e-9 で一致すること（★別経路の確認★）

## 4. 報告する量（★閾値を置かず、数字をそのまま出す★）
天寿率の差の分解：
- 同点の決め方で動く部分 = P_max − P_eval
- 目的の違いで必ず残る部分 = 0.990589612 − P_max
期待寿命の差の分解：
- 目的の違いで必ず失う寿命 = 998.520049 − T_max
- 同点の決め方で動く部分 = T_max − T_eval
