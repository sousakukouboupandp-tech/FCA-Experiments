## 1. 状態キー

decision 境界の状態を `(e, w, n_small, n_large, t)` で表す。
- e：0〜2000 の整数（×20 表現）。**1刻みで動く**（消耗20・草14・傷5×W なので、20刻みにはならない）
- w：0〜K。K 以上は「あふれ状態 w=K」にまとめる（§5）
- n_small：1〜12／n_large：0〜3／t：0〜1000

MODE は decision 境界に限るので状態に含めない（探索・追跡・戦闘は compiled kernel の中に閉じる）。

## 2. 分岐の定義

**サンプリングはしない。**

**到達可能集合（support）の判定：確率が0より大きい枝は、確率の大きさに関わらず support に入れる。確率の打ち切りは使わない。**
- これにより「この状態は物理法則上到達不能」と言える意味を保つ
- 小さい確率を捨てるのは、この後に必要が出た場合の**近似法の候補**であって、最初の support 列挙には混ぜない

**kernel の確率計算（support 列挙とは別）**：数値的に必要なら、確率の打ち切り（1e-15 未満）を使ってよい。切った質量の合計を記録し、条件ごとに報告する。
確率の合計が 1 から 1e-12 以上ずれたら異常として停止する。

## 3. compiled kernel の形式

decision 境界 s と行動 a に対して、`P(τ, s', 終端理由 | s, a)` を返す。
- τ：その行動が終わるまでの歩数（または死ぬまで）
- **開始状態に e を含める。** 体力は物理の遷移そのものに入る（探索の途中で飢え死する、傷の消耗が効く、上限で切られる、捕獲で摂取する）。「e から切り離した kernel」にはできない
- D0 と D_S-exact は**同じ物理 kernel を共有できる**（目的関数に依存しない）
- **D1a は共有できない。** r_t = D(E_t) − D(E_{t+1}) が内部の軌跡に依存するため、行動報酬 R(s,a) = E[Σ γ^k r_{t+k}] を内部の1歩ごとに積算する必要がある
  - **段階0では「正しいが遅い D1a」を作る。速度より正しさ。** 高速化は必要が出てから
  - 条件数は q 3 × E_set 4 × γ 4 = **48条件**

## 4. 到達可能集合の列挙

初期状態（2000, 0, 12, 3, 0）から前向きに展開し、重複を除いて時刻ごとの decision 状態集合を作る。

### 4-0. 層の定義と τ の上限（2026/9/18 訂正。実行中に発見した設計不一致）

**1. 層は1歩時間 t ごと。** 「decision 境界を何回通ったか」を層番号にしない。macro action が τ 歩なら S_t → S_{t+τ} に書き込む（時間の DAG になる）。

**2. τ_max = 100。** 世界の物理から出る（導出）：
- 1歩の消耗は 20 + 5×W で、**最小でも20**
- 行動の途中で体力が増えることはない。**摂取が起きる歩は、そのまま decision 境界に戻る歩**（草は1歩、小物は追跡4歩目の捕獲、大物は仕留めの歩）
- 体力の上限は 2000。傷は消耗を増やすだけで、治っても最小消耗20は変わらない
- → 幾何分布の探索時間には理論上の上限がないが、**身体の有限な体力がそれを100歩以内で切る**

**3. 状態ごとの上限：τ ≤ ceil(E_t / 20)。**
floor ではなく ceil。E_t=1999 なら floor は99だが、100歩目の遷移自体は実行できる。その歩に摂取（捕獲・仕留め）があれば、v02 §1-9 の「全収支を反映してから飢え死を判定」により生き残って decision に戻る場合がある。全体では ceil(2000/20) = 100 なので τ_max = 100 は変わらない。

**4. horizon を越える枝と終端の枝は、未来の decision bucket に入れない。**
t+τ > 1000 の枝は v02 §1-9 の終端規則で処理する。終端状態（飢え死・急所死・天寿）は未来の bucket に入れない。

**rolling buffer は101本**（t から t+100）。

**理論上限**：1時刻あたり 2001 × (K+1) × 12 × 4 ≈ 106万（K=10）。1000時刻で約10.6億。上限でしかないので、実際に測る。

**打ち切りの規則（先に決める）**
- 保持する状態の総数が **2000万** を超えたら、その時点で停止して「時刻ごとの状態数の伸び」だけを報告する
- 実行時間が **30分** を超えたら同様に停止する
- メモリ監視：**列挙プロセス自身の RSS を測り、8GB を超えたら停止する**（PC全体の RAM 使用量は再現可能な基準にならないので、安全監視として別に見るだけ。2026/9/18 に残留プロセスで RAM を使い切った事故があったため）
- 停止した場合は、到達集合の全列挙を諦め、**状態の粗視化か horizon の縮小を新しい決定として記録してから**進む（結果を見てから決めない）

**規模の測定は rolling buffer で行う**（全1000層を同時に保持しない）
```
S_t → 全行動・全 support → S_{t+1} … S_{t+100} に書き込む → S_t を破棄
（101本の bucket を回す。τ ≤ 100 が厳密なので足りる）
```
各時刻について残すのは統計だけ：|S_t|、e・w・n_small・n_large の範囲、累積の生成数、ピーク RSS、実行時間。
後ろ向きに解く段階で各層が必要になったら、**層ごとにディスクへ保存する／再生成する／別の圧縮表現を使う**のどれにするかは、この規模測定を見てから決める。

**記録するもの**：時刻ごとの decision 状態数、累積の一意な状態数、e・w・n_small・n_large の実際の範囲、実行時間、メモリ使用量。

## 5. 傷のあふれ K

K=10 から。**K は世界の物理ではなく solver の近似。**
- P(W ≥ K) の質量
- 初期状態の価値 V
- 初期状態の optimal_set
- 主要な占有率重み付き不一致

の4つが、K=10 → 12 → 15 で収束することを確認する。結論が K に依存していたら、その事実を報告する。

## 6. 寿命の端の処理

t=1000 に到達した状態は終端。**1000歩目の遷移を生き抜いた場合だけ天寿**（v02 §1-9）。
行動の途中で t が 1000 を超える場合も、1歩ずつ判定する（compiled kernel の内部で処理し、τ が horizon を越えないように切る）。

## 7. 数値精度

- 価値は float64
- 同点判定：**|Q_a − Q_b| ≤ atol + rtol · max(1, |Q_a|, |Q_b|)**、**atol = 1e-9、rtol = 1e-12**
- 確率の正規化は行わない（合計が1からずれたら §2 で停止する）

## 8. 正本との一致試験（縮小世界）

本番では重いので、**全状態を完全列挙できる縮小世界**を作って比較する。

縮小の内容（世界の物理の変更ではなく、検証用の縮小版であることを明記する）
- 寿命 20歩
- 体力の上限を縮小（例：200）。消耗・摂取も同じ比で縮小
- 小物 3、大物 2、傷の上限 3

比較するもの：**価値だけでなく、全 decision 状態・全合法行動について Q まで一致すること。**

```
Q_primitive(s, a) == Q_compiled(s, a)   （全状態・全行動）
```

確認する項目：行動の所要歩数 τ、背景の大物回復、傷の治癒、行動途中の飢え死、horizon の境界、急所死、摂取と上限クリップ、γ^τ。

価値だけの一致は偶然でも起こりうるので、**Q まで比べる。**
