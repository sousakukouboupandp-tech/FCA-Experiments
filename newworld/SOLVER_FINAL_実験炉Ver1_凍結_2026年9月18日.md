## 2. dense のアドレス空間

**8,452,224** primitive slot。
```
i = ((((m * 2001 + e) * 11 + w) * 12 + (n_small − 1)) * 4 + n_large)
m : decision=0, search_small=1, chase_1=2, chase_2=3, chase_3=4,
    chase_4=5, search_large=6, combat=7
e : 0..2000 ／ w : 0..10（index 10 は「W ≥ 10 のあふれ」）
n_small : 1..12 → 0..11 ／ n_large : 0..3
```

**E=0 の slot は残すが structural-invalid**（再番号付けしない）。

## 3. structural-valid

**7,920,000** primitive 状態（8,452,224 − 532,224）。
除外されるもの：E=0 の非終端（各 MODE 528、8 MODE で 4,224）、`search_large`／`combat` の N_L=0（各 264,132）＋その E=0 分（各 396）。

## 7. 数値の表現（凍結）

```

```
**float32 には落とさない**（新しい数値誤差要因を持ち込まない）。
numerical tie：`|Q_a − Q_b| ≤ 1e-9 + 1e-12 · max(1, |Q_a|, |Q_b|)`（変更しない）。

## 8. 後ろ向き（backward）

- 価値は **current / next の2層**（primitive なら常に t → t+1 なので101層は不要）
- **decision の方策だけを1000時刻ぶん保存**（強制 MODE には選択がない）
- numerical tie は §7 の式
- `optimal_set` と `selected_for_execution` を両方保存（固定順序：草 → 小物 → 大物）

## 9. 前向き（forward）

- 方策の memmap を**時刻順に読む**
- **decision だけ方策を参照。強制 MODE は強制遷移**
- 占有率も current / next の2層
- **各歩で P(生存) + P(飢え死) + P(急所死) + P(天寿) = 1 を確認する**
- t=999 で非終端を天寿に移す

## 10. 終端（凍結）

- **飢え死・急所死は horizon より優先**
- **終端の生の体力を保持する**（負の値になりうる。0 に切らない）
- **D1a**：生の値を使う
- **D1b**：不利な死（飢え死・急所死）だけ E=0 として評価する
- **天寿では D1b の置換を発動しない**

**実寸で確認した数値（F3）**：急所死で終端の体力が 1980 のとき、**D1a の報酬は +23,600（正）**、D1b は −1,600,000。
**記録の表現**：D1a では adverse death の枝に**局所的な正の即時報酬が存在し得ることを、実寸 kernel の経路で確認した。global optimality は未確認。**
